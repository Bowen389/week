# 262B周线策略与20万元模拟仓

当前唯一运行版本：`WEEK_262B_V1`，已替换原无涨幅过滤版本。仅进行盘后日线模拟记账。

## 选股与交易规则

1. 沪深主板，排除指数、ST、退市名称及当前非上市状态。
2. 使用每周最后一个交易日的完整周线，至少3个交易记录，缺失或停牌周不产生信号。
3. 周收盘>周开盘；|周开盘−周最低|≤0.01元；|周收盘−周最高|≤0.01元。
4. **4%＜周涨幅≤12%**。周涨幅＝周收盘÷信号周之前最后一笔有效收盘−1，绝不是周收盘÷周开盘−1。最多读取周前60个自然日寻找有效收盘，仍无记录则不入选。边界使用Decimal十进制比较。
5. 下一交易日仅在 **0%≤开盘溢价≤4%** 时买入。开盘溢价＝买入日开盘价÷信号周收盘−1。低开、高开超过4%、涨停开盘、缺数据或已持有均跳过，不追补。
6. 买入当天为第0日，**买入后第2个交易日收盘卖出**。例如正常周一买、周三收盘卖；按交易所日历计算，停牌不重置持有天数。收盘跌停或停牌则延后退出。
7. 初始现金20万元，每批先过滤开盘条件，再将可用现金等额分配给通过者；单批投入上限20万元，100股整数手，计入费用后不足一手跳过。同日收盘卖出回款不用于当日开盘买入。
8. 佣金单边万三、最低5元，卖出印花税万五；无额外滑点假设，不保证真实开盘成交。

262B沿用研究版本名称。历史研究原统计262笔，回放发现冠豪高新（2025-11-07信号）和中国中冶（2025-08-08信号）的实际周涨幅均恰为4%，原浮点计算误判为大于4%。严格执行上述规则后对应260笔，单笔平均净收益仍约+0.70%；历史统计不是20万元组合收益，也不代表未来表现。

## 运行与输出

北京时间每日18:20运行、21:20补跑；仅周最后交易日生成周线候选，其他交易日更新账本。买卖使用当天日线在18点后记账，不是实时委托。GitHub定时运行可能延迟。

- `signals/YYYY-MM-DD/signals.json`、`README.md`：262B盘后候选、周前收盘、周涨幅、策略版本。开盘溢价须下一交易日才能确认，候选不等于买入名单。
- `reports/weekly_counts.csv`、`weekly_counts.json`：每周候选数、开盘通过数、实际模拟买入数及版本，零信号也记录。
- `state/account.json`：现金、持仓、已处理日期、买卖和跳过事件；重复运行不重复交易。
- `reports/latest.json`：最近检查、现金持仓、参数及版本。
- `reports/data_errors.json`：接口异常，失败日期不推进，补跑重试。
- `reports/262b_validation.json`：部署前历史回放核对结果及浮点边界修正。

更新保留已有现金、持仓、事件和日期账本；已有持仓仍按原计划退出。旧版本候选不直接用于262B买入。部署前没有模拟持仓，本次没有补写研究期历史交易。

## 信号推送配置与补发

在仓库 Settings → Secrets and variables → Actions 添加 Repository secret：`SERVERCHAN_SENDKEY`，值填写你自己的 Server酱 SendKey（兼容旧名称 `SENDKEY`）。不要将密钥提交到代码、报告或聊天中。

每次成功扫描并提交账本后，工作流会推送尚未收到成功确认的周信号，包括零候选结果。推送确认保存在 `state/notifications.json`，与账户成交账本分离。未配置密钥或推送失败时，信号及账本仍然保留，工作流明确提示原因；补齐配置后，在 Actions 重跑最新工作流即可补发。已完成的交易日不会重复记账，已确认的周信号不会重复发送。
