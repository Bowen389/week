# 完整周线信号与20万元模拟仓

依据上传的 strategy_report_and_trades.xlsx 中“口径与限制”部署。仅模拟记账，不连接券商。

## 固定规则

- 沪深主板股票，严格排除指数、ST、退市名称及当前非上市状态。每日再次检查 isST 和交易状态。
- 按交易所日历确定每周最后一个交易日，使用该周完整日线聚合周线；至少3个交易记录，缺失/停牌周不产生信号。
- 周收盘>周开盘；|周开盘−周最低|≤0.01元；|周收盘−周最高|≤0.01元。不附加 week1 仓库的市值条件。
- 信号后下一交易日开盘价模拟买入，买入当天为第0日，第2个交易日收盘价卖出。例如正常周一买、周三卖，节假日顺延。计数使用交易所日历，停牌不重置持有天数。
- 初始资金200000元，复用现金；每批信号按可用现金等额分配，投入上限20万元，100股整数手，不融资；不足一手跳过。
- 涨停开盘不模拟买入，缺数据/停牌不追补买入；收盘跌停或停牌延后退出。仅为保守日线成交近似，不代表真实订单可成交。
- 佣金单边万三、最低5元，卖出印花税万五；成交按开盘/收盘，不额外假设滑点。

## 时间与文件

北京时间每日18:20运行，21:20补跑。非周末交易日只更新模拟仓；周最后交易日18点后生成信号。每日运行是为了执行下一周买卖，而不是每天重新选周线。

- `signals/YYYY-MM-DD/signals.json` 与 `README.md`：按实际周末交易日独立归档，包含周涨幅与周收盘价。
- `reports/weekly_counts.csv`、`weekly_counts.json`：每周信号数，零信号也归档。
- `state/account.json`：现金、持仓、逐笔事件、已处理日期，重复运行不重复交易。
- `reports/latest.json`：最近检查和账户状态。
- `reports/data_errors.json`：接口错误；失败不推进该日状态，补跑重试。

买卖使用当天日线在18点后记账，明确属于盘后日线模拟，不冒充实时委托。部署当日开始，不补写部署前的虚拟交易。GitHub定时调度可能延迟，可手动运行 Actions。

## 表格核查与追高条件

原表1648笔，1448笔为主板代码，另200笔混入指数。不能直接把原汇总视作股票策略绩效。例如兴业股份2025-01-27买入至2025-02-06收盘为−30.56%，浙江建投2024-11-25买入至11-27收盘为−26.80%。

但原表不含信号周OHLC及信号周收盘价，无法计算周涨幅或次周开盘溢价，无法确认两者与大亏损的关系，因此本次没有任意增加周涨幅/高开阈值。新归档保存这些字段，后续可用实际样本验证。原表未逐日还原历史ST，未计成本及涨跌停成交限制，不能视作严格历史回测。
